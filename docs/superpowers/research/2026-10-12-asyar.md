# Asyar Architecture and UX Survey

An analysis of [Asyar](https://github.com/Xoshbin/asyar) (commit `0da22f7e595279f7e91872cd7f112a66671473da`,
2026-10-12) to inform kb's design, backlog, and architecture.

## 1. Summary

Asyar is a Rust and Tauri launcher with a Svelte 5 frontend, Raycast-like ambitions, and an extensive extension SDK.
Its webview architecture forces extreme complexity around window resizing, occlusion, and frame synchronization.
kb's native GPUI Kit implementation is far leaner, lighter, and faster, avoiding that entire class of problems.
However, Asyar's native macOS paste mechanism, clipboard privacy safeguards, and benchmark probes are proven.
Because Asyar is licensed under GPL-3.0, kb must not copy any code; we adopt patterns clean-room and evaluate MIT crates.

### Top five adoptions for kb

1. **Simulate paste via `CGEventPostToPid`**: Use macOS CoreGraphics `CGEventCreateKeyboardEvent` and `CGEventPostToPid`
   after an `AXIsProcessTrusted` accessibility check to implement kb's upcoming _Paste to the frontmost app_ task
   without third-party crates.
2. **Filter private pasteboard types**: Inspect `NSPasteboard` types for `org.nspasteboard.ConcealedType`,
   `org.nspasteboard.TransientType`, and `AutoGeneratedType` to ensure password-manager secrets are never captured or
   retained.
3. **Adopt process-group `phys_footprint` and `powermetrics` in benchmarks**: Enhance kb's benchmark probes
   (`tools/bench/`) with Asyar's external attribution methods for whole process groups, wakeups per second, and idle
   disk writes.
4. **Anchor window with top-weighted monitor arithmetic**: Adapt Asyar's `TopWeighted { bias: 0.16 }` positioning
   formula so kb stays consistently placed across multiple monitors and never collides with the Dock or menu bar.
5. **Evaluate `fend-core` for inline calculations**: If kb adds an inline calculation entry type or hero, adopt the
   permissive MIT crate `fend-core` (v1.5.8) for fast, unit-aware natural language math.

## 2. Asyar at a glance

- **Stack**: Rust 2021 + Tauri v2 (`tauri` 2.12.3) backend; Svelte 5 (runes) + TypeScript + Vite frontend; pnpm
  monorepo (`asyar-launcher`, `asyar-sdk`, `asyar-ext-builder`, `benchmarks`).
- **Architecture**:
  - `asyar-launcher/src-tauri`: Tauri application, command handlers, and window lifecycle.
  - `crates/asyar-platform`: OS-level window, keyboard, display, and input simulation abstractions.
  - `crates/asyar-search`: In-memory fuzzy ranking engine (`fuzzy-matcher` SkimMatcherV2, tier classification).
  - `crates/asyar-storage`: Pooled SQLite persistence (`rusqlite`, `r2d2`, AES-GCM encryption, in-memory FTS5).
  - `crates/asyar-calculator`: Natural-language calculation and conversion engine (`fend-core`, `evalexpr`).
  - `asyar-launcher/src`: Svelte 5 frontend application (launcher, settings, HUD, built-in features).
  - `asyar-sdk`: TypeScript SDK for extension authors (`ExtensionContext`, services, workers).
  - `asyar-ext-builder`: Bundler and validation pipeline for third-party extensions.
  - `benchmarks`: Swift CLI (`benchtool.swift`) and shell harness comparing Asyar against Raycast v1 and v2.
- **Maturity**: Active development (release `0.1.1-51`, PR #856, 452 test suites across Rust and TypeScript). Supports
  macOS, Windows, and Linux (X11 and Wayland).
- **Licence**: **GPL-3.0-only**. kb is **MIT**. kb must not copy any Asyar source code or GPL dependencies. All
  findings below describe behaviors, data structures, and algorithms in kb's own words. Only permissively licensed
  dependencies (MIT, Apache-2.0, BSD) are considered for adoption.

`crates/asyar-platform/src/input.rs` and `src-tauri/src/commands/input.rs` solves the exact problem of kb's open _Paste_
task:

1. Call `AXIsProcessTrusted()` to verify Accessibility permissions.
2. Order out the launcher window so focus returns to the frontmost application.
3. Wait 50 ms (`std::thread::sleep(Duration::from_millis(50))`) for the OS window server to reactivate the prior app.
4. Retrieve the frontmost application's PID via `NSWorkspace.sharedWorkspace.frontmostApplication.processIdentifier`.
5. Synthesize `Cmd+V` directly to that PID using `CGEventCreateKeyboardEvent` and `CGEventPostToPid` with
   `kVK_ANSI_V = 9` and `kCGEventFlagMaskCommand = 0x00100000`.

## 4. UX patterns to translate

### Pattern 1: Action Panel Popup (⌘K)

- **What it is and when it appears**: A floating action menu docked at the bottom-right of the window directly above
  the footer bar, opened via `⌘K` or by clicking the Actions footer button.
- **The keys and flow**:
  1. User presses `⌘K` from search results or detail view.
  2. Popup appears anchored at `bottom: calc(footer_height + 12px)`, `right: 12px`, `width: 350px`, `max-height: 243px`.
  3. Focus automatically moves to the search input docked at the **bottom** of the popup after 50 ms.
  4. Typing filters the actions list in real time.
  5. `↑` / `↓` moves selection through the flat list.
  6. `Enter` immediately executes the selected action and closes the popup.
  7. `Escape`: if search text is present, clears search text; if search text is already empty, closes the popup and
     returns focus to the main list.
- **States and edge cases**:
  - Displays category headers with thin hairline dividers (`height: 1px`, negative side margin to extend edge-to-edge).
  - Destructive actions (e.g. Delete) render with danger accent color (`--accent-danger`).
  - Empty state displays centered subtle message ("No matching actions").
  - The popup closes _before_ awaiting any confirmation dialogs so the user cannot double-trigger actions.
- **Svelte component**: `asyar-launcher/src/components/layout/ActionListPopup.svelte:1-280`.
- **Relation to kb**: Confirms kb decision **D9** (action panel anchored to bottom-right, search at the bottom,
  category dividers, Esc clears search before closing).

### Pattern 2: Docked Footer Action Cluster

- **What it is and when it appears**: Persistent bar at the bottom of the window (`height: 40px`, border-top hairline).
- **The keys and flow**:
  - Left slot: displays contextual status (e.g. `Ready • N results`, active error notices, or current file path).
  - Right slot: displays the primary action label in bold followed by an `↵` keycap, followed by a vertical separator
    line (`width: 2px`, `height: 11px`), followed by the `Actions` label and a `⌘K` keycap.
- **States and edge cases**:
  - When an update or background notice is ready, a pill badge with a pulsing dot appears to the left of the actions.
  - In compact window mode (96 px), the footer is hidden or cropped.
- **Svelte component**: `asyar-launcher/src/components/layout/BottomActionBar.svelte:1-276`.
- **Relation to kb**: Confirms kb decisions **D8** and **D14**. kb extends this by adding secondary (`⌘↵`) and tertiary
  (`⇧⌘↵`) action hints in the right cluster.

### Pattern 3: Argument Dropdown & Search Accessories

- **What it is and when it appears**: When a selected command requires or accepts arguments, chips are embedded
  directly inside the search bar header to the right of the command icon.
- **The keys and flow**:
  - User selects a parameterized command.
  - An argument chip appears in the search header (e.g., `[Scope: All ▾]`).
  - Clicking the chip or pressing `Tab` opens an accessory dropdown menu.
  - Dropdown has an embedded search input at the top (`SearchBarAccessoryDropdown.svelte:120`).
  - Typing narrows the options; `Enter` commits the value and advances focus to the next parameter.
- **States and edge cases**:
  - Required vs optional arguments have distinct border and label styling.
  - Incomplete required arguments display an inline validation warning in the footer (`Required: argument name`).
  - List navigation does not wrap at the edges; it stops at the first and last elements.
- **Svelte component**: `asyar-launcher/src/components/search/SearchBarAccessoryDropdown.svelte:1-396` and
  `ArgumentDropdownChip.svelte`.
- **Relation to kb**: New idea for future parameterizable commands (TODO task `3g6H`). Provides a reference for
  handling interactive command argument inputs.

### Pattern 4: Resizable Split Pane with Drag Handle

- **What it is and when it appears**: When viewing search results alongside a preview panel, a subtle vertical separator
  divides the list (left) and detail (right).
- **The keys and flow**:
  - The separator has an active hover/drag target (`split-view-handle`).
  - Dragging left or right resizes the pane within clamped boundaries (`minLeftWidth: 200px`, `maxLeftWidth: 800px`).
  - Window cursor switches to `ew-resize` during drag.
- **States and edge cases**:
  - Selection scroll sync: changing selection while the pane is open triggers `scrollSelectedIntoView` with
    `requestAnimationFrame` so the active item never scrolls out of view.
- **Svelte component**: `asyar-launcher/src/components/list/SplitView.svelte:1-75`.
- **Relation to kb**: Compares with kb decision **D11** (kb chose a fixed 34% split width for predictability). Confirms
  the need for strict selection scroll synchronization during pane transitions.

### Pattern 5: Non-activating Floating HUD Toast

- **What it is and when it appears**: Transient overlay window for background actions (e.g. "Copied to clipboard",
  "Note saved"), positioned at the bottom-center of the screen containing the mouse cursor.
- **The keys and flow**:
  - Action fires (e.g. quick note capture or background task).
  - Main launcher panel hides.
  - A small floating HUD panel (360×80 px) appears 80 px above the bottom screen edge.
  - Auto-dismisses after a configurable timeout (default 2000 ms).
- **States and edge cases**:
  - Non-activating panel (`NSWindowStyleMaskNonActivatingPanel` / `1 << 7` style mask) so it never steals keyboard
    focus from the target application.
  - Can display a spinner for indeterminate background tasks.
- **Svelte component**: `asyar-launcher/src-tauri/src/hud_window/service.rs:1-120`.
- **Relation to kb**: Informs kb decision **D17** (copy feedback notice). While kb currently renders notifications
  inside the panel window, a dedicated non-activating NSPanel is the standard Raycast-like pattern for actions that
  dismiss the launcher.

### Pattern 6: Hierarchical Escape Keystroke Flow

- **What it is and when it appears**: How the Escape key behaves across nested UI layers.
- **The keys and flow**:
  1. If an action popup (⌘K) or filter dropdown (⌘P) is open with a query: clears the popover query.
  2. If the popover query is empty: closes the popover and returns focus to the underlying list.
  3. If on a sub-screen (detail view, refresh report): navigates back to the root search list.
  4. If on the root search list with query text: clears the search query text.
  5. If on the root search list with an empty query: hides the launcher panel.
- **Svelte component**: `asyar-launcher/src/components/layout/ActionListPopup.svelte:68-80` and
  `src/routes/+page.svelte`.
- **Relation to kb**: Confirms kb's Esc handling ladder across all screens.

### Pattern 7: Empty State View

- **What it is and when it appears**: Shown when search query yields zero matches.
- **The keys and flow**:
  - Displays a large icon (48 px), a bold title ("No matching entries found"), and a sentence specifying the query:
    `No entries match "<query>"`.
  - The query string is highlighted in monospace text.
  - The footer action button changes to a primary recovery action (e.g. `Refresh ↵`).
- **Svelte component**: `asyar-launcher/src/components/feedback/EmptyState.svelte:1-60`.
- **Relation to kb**: Confirms kb decision **D10** (Raycast empty view format).

## 6. Patterns worth adapting (non-UI)

### Pattern A: Direct `CGEventPostToPid` paste synthesis

- **Description**: Synthesizing `Cmd+V` directly to the target application's process ID rather than broadcasting a
  global event.
- **How it works**:
  1. Check `AXIsProcessTrusted()` from ApplicationServices framework.
  2. Order out the launcher window.
  3. Sleep for 50 ms to allow macOS window manager to restore active focus to the previous application.
  4. Fetch `NSWorkspace.sharedWorkspace.frontmostApplication.processIdentifier`.
  5. Use `CGEventCreateKeyboardEvent(NULL, 9, true)` and `CGEventSetFlags(event, kCGEventFlagMaskCommand)`.
  6. Call `CGEventPostToPid(pid, event)` for key down, then repeat for key up.
- **Affects**: kb TODO task **Paste to the frontmost app**.

### Pattern B: Pasteboard Privacy Classification

- **Description**: Inspecting `NSPasteboard` type identifiers before reading or storing clipboard content to respect
  password manager privacy signals.
- **How it works**:
  - Query `NSPasteboard.generalPasteboard.types`.
  - Check for `org.nspasteboard.ConcealedType` (1Password), `org.nspasteboard.TransientType`, and
    `org.nspasteboard.AutoGeneratedType`.
  - If any match, abort capture or mark content as transient/redacted.
- **Affects**: Future clipboard history or sensitive snippet expansions in kb.

### Pattern C: Top-weighted monitor placement

- **Description**: Display-agnostic calculation that anchors the window at a fixed top-biased vertical fraction while
  clamping within the usable desktop work area.
- **How it works**:
  - Horizontal center: `monitor.x + (monitor.width - window_width) / 2.0`.
  - Vertical position: `monitor.y + monitor.height * 0.16` (16% top bias).
  - Clamp coordinates into display work area (bounds minus Dock and menu bar).
- **Affects**: `crates/kb-app/src/panel.rs` and `window_size.rs`.

### Pattern D: Process-group external benchmarking

- **Description**: Measuring app footprint externally across its entire process group using `libproc` and
  `powermetrics`.
- **How it works**:
  - Query `phys_footprint` across all child and helper processes attributed to the root process.
  - Run `powermetrics` to sample interrupt wakeups per second during deep idle.
  - Use `CGWindowListCopyWindowInfo` polling to measure exact window presentation latency without code probes.
- **Affects**: `tools/bench/` probes and `docs/guides/methodology.md`.

### Pattern E: Deterministic shortcut conflict resolution

- **Description**: A tie-breaking hierarchy for shortcut collisions.
- **How it works**:
  - Liveness check wins first (registered active action beats stale action).
  - Newer `created_at` timestamp wins second.
  - Lexicographical object ID wins third to ensure identical resolution across multiple instances.
- **Affects**: `crates/kb-app/assets/catalog.toml` override merging (D18).

## 7. What kb should not copy, and where kb already does better

### 1. Webview runtime and resize synchronization

- **Asyar**: Uses Tauri with a WKWebView frontend. Resizing the window while expanding results requires complex
  `CATransaction` pre-commit handlers, sentinel polling loops, and private WebKit SPI overrides to prevent visual
  tearing and white flashes.
- **kb advantage**: Built natively on GPUI Kit with Metal. GPUI renders every frame synchronously and natively,
  achieving sub-10 ms response times with zero webview overhead.

### 2. Search list DOM instantiation

- **Asyar**: Renders search results using raw Svelte `{#each}` DOM nodes. Large result sets degrade render time and
  DOM memory.
- **kb advantage**: GPUI Kit provides natively retained, virtualized list components that scale effortlessly to
  thousands of entries.

### 3. Action ergonomics

- **Asyar**: Restricts the footer to a single primary action (`↵`) and opens a flat action menu on `⌘K`.
- **kb advantage**: Fully implements Raycast's hierarchical keyboard ladder (`↵`, `⌘↵`, `⇧⌘↵`) in D7–D8, alongside
  nested action submenus (`More… ›`, `Links… ›`) in D9.

### 4. Configuration architecture

- **Asyar**: Relies on a dynamic JSON file (`settings.dat`) written by an external plugin, with potential runtime schema
  desynchronization.
- **kb advantage**: Uses a compile-time validated `catalog.toml` deep-merged under a human-readable `config.toml` (D18),
  ensuring type safety and clear defaults.

### 5. Memory footprint

- **Asyar**: Idles at ~150–250 MiB due to WebKit runtime processes, helper daemons, and JavaScript runtimes.
- **kb advantage**: A pure Rust binary idling at ~30–40 MiB with zero external runtime dependencies.
